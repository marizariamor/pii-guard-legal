# CLAUDE.md — правила проекта для AI-агентов

## О проекте
PII Guard Legal — локальный контур обезличивания персональных данных (ПДн) в юридических документах перед отправкой в LLM. Требования: `PRD.md`.

## Главное правило
**Ни одно исходное ПДн не должно попасть в текст, который уходит в модель.** Любое изменение, увеличивающее число утечек на эталонном наборе, недопустимо.

## Структура
- `pii_guard/detectors.py` — детекторы ПДн (один детектор = одна функция, возвращает список `Entity`).
- `pii_guard/anonymizer.py` — обезличивание, обратная подстановка, финальная проверка `find_leaks`.
- `pii_guard/cli.py` — командная строка.
- `app.py` — веб-демо (Streamlit).
- `tests/` — unit-тесты (pytest).
- `evals/golden/` — синтетические документы с ПДн и эталоном `*.json`.
- `evals/clean/` — документы без ПДн для проверки ложных срабатываний.
- `evals/run_eval.py` — eval-гейт; код возврата ≠ 0 при нарушении порогов.

## Как работать над задачей
1. Сначала прочитай `PRD.md` и найди, какое требование закрывает задача.
2. Декомпозируй: детектор → тест → пример в `evals/` → прогон.
3. Новый тип ПДн = новый детектор + unit-тесты (позитивные и негативные) + минимум 2 примера в `evals/golden/`.
4. Найден пропуск ПДн → сначала добавь его в eval (тест падает), потом исправь детектор.
5. Перед завершением задачи обязательно:
   ```
   python -m pytest -q
   python evals/run_eval.py
   ```

## Конвенции
- Python 3.11+, без внешних зависимостей в ядре `pii_guard` (только стандартная библиотека).
- Только синтетические данные в тестах и eval. Реальные ПДн в репозитории запрещены.
- Числовые ПДн проверяются контрольной суммой, где она есть (ИНН, СНИЛС, карты), чтобы не ловить суммы и номера договоров.
- Метки имеют вид `[ТИП_N]`, одна и та же сущность в документе получает одну и ту же метку.
- Сообщения коммитов: `feat:`, `fix:`, `test:`, `docs:`, `ci:`.

## Пороги eval-гейта
- Утечки ПДн: **0**
- Полнота обнаружения: **≥ 95%**
- Ложные срабатывания на `evals/clean/`: **0**
