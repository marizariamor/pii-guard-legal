# 🛡️ PII Guard Legal

![CI](https://github.com/marizariamor/pii-guard-legal/actions/workflows/ci.yml/badge.svg)

**Контур обезличивания персональных данных в юридических документах перед отправкой в LLM.**

Юридические компании хотят использовать LLM для разбора документов клиентов и подготовки заявлений, но не могут отправлять во внешнюю модель персональные данные (152-ФЗ, адвокатская тайна). PII Guard — локальный слой между документом и моделью: находит ПДн, заменяет их метками, проверяет, что ничего не утекло, и возвращает данные на место в ответе модели.

```
Документ клиента ──► обезличивание ──► проверка утечек ──► LLM ──► ответ с метками ──► обратная подстановка ──► готовый текст
                     [ФИО_1], [ИНН_1]   0 ПДн? иначе стоп          (локально)
```

## Пример

**Было:**
```
от Смирнова Алексея Викторовича, паспорт серия 45 18 № 734521,
проживающего по адресу: г. Москва, ул. Профсоюзная, д. 84, кв. 112, тел. +7 (916) 245-37-81
...
12 августа 2026 года я, Смирнов А.В., приобрёл смартфон стоимостью 45 990 рублей (чек № 0042317).
```

**Уходит в модель:**
```
от [ФИО_1], паспорт серия [ПАСПОРТ_1],
проживающего по адресу: [АДРЕС_1], тел. [ТЕЛЕФОН_1]
...
12 августа 2026 года я, [ФИО_1], приобрёл смартфон стоимостью 45 990 рублей (чек № 0042317).
```

- «Смирнова Алексея Викторовича» и «Смирнов А.В.» — один человек → одна метка `[ФИО_1]`.
- Суммы, номер чека, даты и статьи законов остаются: модели нужен смысл документа.

## Что распознаётся

| Тип | Примеры форматов | Защита от ложных срабатываний |
|---|---|---|
| ФИО | полное, в падежах, «Фамилия И.О.», «И.О. Фамилия» | отчество обязательно для полной формы |
| Телефон | +7 (916) 245-37-81, 8 903 512 44 09, +79274418820 | 8… и +7… — один номер |
| Email | name@mail.ru | — |
| Паспорт РФ | 45 18 № 734521, 40 15 номер 662180 | только рядом со словами «паспорт» / «серия» |
| ИНН | 10 и 12 цифр | контрольная сумма |
| СНИЛС | 123-456-789 00 | контрольная сумма |
| Банковская карта | 2200 2917 0342 3664 | алгоритм Луна |
| Расчётный счёт | 20 цифр | — |
| Адрес | г. …, ул. …, д. …, кв. … | нужна улица и дом |

## Качество: тесты и eval-гейт в CI

При каждом изменении GitHub Actions запускает 35 unit-тестов и eval на эталонных документах. **Изменение блокируется**, если нарушен хотя бы один порог:

| Метрика | Порог | Текущий результат |
|---|---|---|
| Утечки ПДн | 0 | **0** |
| Полнота обнаружения | ≥ 95% | **100%** (58/58 на 8 документах) |
| Ложные срабатывания на документах без ПДн | 0 | **0** |

Эталонный набор (`evals/golden/`): претензия потребителя, обращение о взыскании долга по расписке, заявление работодателю, договор оказания юридических услуг, чат клиента, доверенность, жалоба, иск о взыскании алиментов. Все данные синтетические, контрольные суммы сгенерированы.

Пример реальной пользы eval-гейта: при первом прогоне он поймал, что адрес в Санкт-Петербурге распознаётся не целиком (заглавная буква после дефиса). Ошибка исправлена до того, как попала в основную ветку.

## Как запустить

```bash
python -m pii_guard evals/golden/01_pretenziya_potrebitelya.txt   # командная строка
pip install -r requirements.txt && streamlit run app.py            # веб-демо
pip install -r requirements-dev.txt && python -m pytest -q         # тесты
python evals/run_eval.py                                           # eval-гейт
```

Использование в коде:
```python
from pii_guard import safe_prompt, deanonymize

result = safe_prompt(document_text)          # бросит PIILeakError, если ПДн остались
answer = call_llm(result.text)               # в модель уходит только обезличенный текст
final = deanonymize(answer, result.mapping)  # подстановка ПДн — локально
```

## Как устроена разработка

Проект сделан в **Claude Code** по правилам из [`CLAUDE.md`](CLAUDE.md):
1. [`PRD.md`](PRD.md) — проблема, пользователи, метрики успеха, объём MVP.
2. `CLAUDE.md` — правила для агентов: структура, конвенции, порядок работы (детектор → тест → пример в eval → прогон), пороги качества.
3. Каждый тип ПДн — отдельный детектор с позитивными и негативными тестами.
4. Найденный пропуск сначала добавляется в eval (тест падает), потом исправляется.

Ядро без внешних зависимостей: только стандартная библиотека Python.

## Ограничения и следующие шаги

- ФИО и адреса в свободной форме (без отчества, без улицы) → подключить NER (Natasha).
- Падеж при обратной подстановке: подставляется форма в именительном падеже; согласование по падежам в ответе модели — через pymorphy.
- Сканы и фото документов → OCR.
- Подключение LLM: извлечение полей и генерация заявлений по шаблонам (ИИ-делопроизводитель).
- Журнал отправок для службы ИБ.
